NAME
  tstamp - local-first terminal timestamp utility

SYNOPSIS
  tstamp [FORMAT]
  tstamp-a [FORMAT]
  tstamp set FORMAT
  tstamp stop | status | format | export | reset
  tstamp help | man | examples | version

DESCRIPTION
  TStamp prints a START line before each command you run and an END
  line when it finishes, with the exit code and duration:

  [T1][2026-10-29 19:42:01.100] START: npm run build
  Build failed.
  [T1][2026-10-29 19:42:04.200] END: npm run build | EXIT=1 | DURATION=3.10s

  A small hook loaded into your shell does the work. There is no
  background service, no network access and no telemetry. Every
  terminal gets its own session ID (T1, T2, ...), so lines from
  different terminals can be told apart.

COMMANDS
  tstamp [FORMAT]
      Enable tracking in this terminal. FORMAT is a number 1-5 or a
      custom format string (see FORMATS) and applies to this terminal
      only. Without FORMAT, the saved default is used. Needs the hook
      loaded in this terminal (see INSTALLATION).

  tstamp-a [FORMAT]
      Enable tracking in every terminal that has the hook loaded:
      existing terminals start at their next prompt, new ones from
      their first command. With FORMAT, the saved default format is
      changed first. Global tracking switches itself off after a
      reboot.

  tstamp stop
      Stop global tracking and tracking in this terminal. Other
      terminals that only follow the global setting stop at their next
      prompt, with no restart. A terminal where you enabled tracking
      yourself with "tstamp" keeps tracking until you run "tstamp stop"
      in that terminal.

  tstamp status
      Show this terminal's state and session ID, the global state, the
      default format and the live sessions.

  tstamp format
      List the timestamp formats with live examples. The current
      default is marked with *.

  tstamp set FORMAT
      Change the saved default format (a number 1-5 or a custom string).

  tstamp export [-o FILE] [SESSION...]
      Merge the session logs into one report in time order, using the
      saved default format. Give session IDs (for example T1 T2) to
      include only those sessions. The report goes to the screen, or
      to FILE with -o (an existing file is never overwritten). Exit
      status 1 means no matching logs were found.

  tstamp help
      Show a short command summary.

  tstamp man
      Show this manual (through "less" when it is available).

  tstamp examples
      Show usage examples.

  tstamp version
      Show the installed version.

  tstamp reset
      Restore the default configuration (default format 4). It does not
      change the global setting and does not delete logs.

  tstamp hook add|remove [--yes] [FILE]
      Add or remove the TStamp block in your Git Bash startup file
      (default ~/.bashrc), so new terminals load the hook. A backup is
      made first and nothing changes without your confirmation.

  tstamp run COMMAND [ARGS...]
      Run one command with START and END lines, its exit code and its
      duration, written to the same log as your other windows. It works
      from any shell, including CMD, which cannot be tracked
      automatically. It returns the exit code of the command.

FORMATS
  ID  Meaning                       Format string
  --  ----------------------------  ---------------------------
  1   Hours and minutes             %H:%M
  2   Hours, minutes, seconds       %H:%M:%S
  3   Date and time                 %Y-%m-%d %H:%M:%S
  4   Date, time, milliseconds      %Y-%m-%d %H:%M:%S.%3N
  5   Date, time, UTC offset        %Y-%m-%d %H:%M:%S %z

  Format 4 is the default. A custom format is any string with at
  least one % and no line break, written with standard date/strftime
  codes. Besides the usual codes, %3N gives milliseconds, %6N gives
  microseconds and %N gives nanoseconds (padded with zeros). Quote
  custom formats so the shell does not change them:

    tstamp set "%d/%m/%Y %H:%M"

CONFIGURATION
  State lives in ~/.tstamp. To use another folder, set TSTAMP_HOME
  before starting the terminal.

  config            Plain key=value file. It currently holds format=.
  enabled           Exists only while global tracking is on. It records
                    which boot created it and is ignored after a reboot.
  sessions/Tn/pid   One folder per live terminal (Tn is its session ID).
                    IDs of closed terminals are reused.
  logs/Tn-PID.log   One log file per terminal.

  Format priority in a terminal: its own format (tstamp N), then the
  saved default, then format 4.

  Reboot detection: where /proc/sys/kernel/random/boot_id exists it is
  used. Git Bash has none, so the boot time is estimated from the
  uptime counter instead.

OUTPUT AND LOGS
  Console lines look like this, with the timestamp in your format:

  [SESSION][TIMESTAMP] START: command
  [SESSION][TIMESTAMP] END: command | EXIT=code | DURATION=seconds

  Each log file holds one tab-separated line per event: time in
  microseconds since 1970, session ID, shell PID, START or END, exit
  code and duration in microseconds (END only), and the command text
  (tabs and line breaks become spaces).

  The tstamp and tstamp-a commands are not tracked themselves.
  Commands run while tracking is off are not recorded. A pipeline is
  recorded as one command, with the exit status the shell reports.

EXAMPLES
  Run "tstamp examples" for a list of ready-to-use commands.

TROUBLESHOOTING
  "tstamp: another DEBUG trap is already set"
      Another tool (for example bash-preexec) already uses the shell's
      DEBUG trap. TStamp will not replace it, so tracking is not
      installed in that terminal.

  "tstamp: bash 4.4 or newer is required"
      Your bash is too old. Check it with: bash --version

  tstamp-a changed nothing in an open terminal
      Only terminals that loaded the hook can follow it. Open a new
      terminal, or run this in that terminal:
        source /path/to/tstamp/shells/bash.sh

  A terminal keeps tracking after "tstamp stop" elsewhere
      That terminal was enabled with "tstamp". Run "tstamp stop" in it.

  Tracking is off after a reboot
      This is intended. Run tstamp-a again.

  No lines appear
      Run "tstamp status". Tracking must be on for this terminal, and
      the "State dir" line must show the folder you expect.

PRIVACY
  TStamp is local only. It makes no network connections, sends no
  telemetry and needs no account, cloud service or background service.

  Logs contain the full text of every tracked command, including any
  passwords or tokens typed on a command line. They are stored
  unencrypted in ~/.tstamp/logs, and the same text is printed in your
  terminal. Run "tstamp stop" before typing secrets, and delete old
  logs when you no longer need them:

    rm -rf ~/.tstamp/logs

INSTALLATION
  Pick the section for your system. You only need that one.

  Windows (Git Bash)
    1. Install Git for Windows if you do not have it, because TStamp
       runs inside Git Bash: https://git-scm.com/download/win
    2. Download tstamp-windows-setup.exe from
       https://github.com/abinaze/tstamp/releases/latest and run it.
       Windows SmartScreen may warn because the installer is not
       code-signed: choose More info, then Run anyway.
    3. Leave "Load TStamp in every new Git Bash window" ticked. The
       installer backs up ~/.bashrc first, then adds a short block
       between "# >>> tstamp >>>" and "# <<< tstamp <<<".
    4. Open a new Git Bash window and type: tstamp-a
    No administrator rights are needed. Files go to
    %LOCALAPPDATA%\Programs\TStamp.

  Debian and Ubuntu
    1. Download tstamp.deb from the latest release page.
    2. Run: sudo apt install ./tstamp.deb
    3. Run once: tstamp hook add
    4. Open a new bash window and type: tstamp-a

  Linux, macOS and WSL, without sudo
    Run:
      curl -fsSL \
        https://github.com/abinaze/tstamp/releases/latest/download/get.sh \
        | bash
    This downloads tstamp-unix.tar.gz, checks it against
    SHA256SUMS.txt, and installs for your user in ~/.local. The checksum
    catches damaged downloads only. It edits no startup file unless you
    add "-s -- --hook" after "bash". Or unpack tstamp-unix.tar.gz and
    run: bash install.sh
    After installing, run "tstamp hook add" if you did not use --hook.

  macOS
    The built-in bash 3.2 is too old, and Terminal opens zsh, which
    TStamp does not support yet. Install a current bash with
    "brew install bash", then start it by typing: bash

  Without a package
    To try TStamp in one terminal (closing it removes everything):
      source /path/to/tstamp/shells/bash.sh

UNINSTALLATION
  Windows
    Open Windows Settings, then Apps, find TStamp and choose Uninstall.
    It removes the block from ~/.bashrc (after a backup) and deletes the
    program files. It asks whether to delete your settings and logs in
    ~/.tstamp; the default answer is No.

  Debian and Ubuntu
    Run "tstamp hook remove", then: sudo apt remove tstamp

  Linux, macOS and WSL (install.sh or get.sh)
    Run: bash ~/.local/share/tstamp/uninstall.sh
    It removes the startup-file block (after a backup), the tstamp and
    tstamp-a commands and the program files, then asks before deleting
    ~/.tstamp (default: No).

  Any system
    Backups of your startup file stay next to it, named like
    .bashrc.tstamp-backup-DATE-TIME. Delete them when you no longer
    need them.

LIMITATIONS
  Not yet tested: full-screen programs (vim, less, ssh), several
  commands on one line, background jobs and very long-running commands.
  Only bash is supported.
